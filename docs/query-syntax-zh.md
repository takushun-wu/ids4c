# ids4c 特化查询语法

[English](query-syntax.md)

本文说明 ids4c 在普通 IDS 之上提供的查询、模糊匹配和预处理语法。它们主要用于查询字符串，不建议直接作为上游 IDS 数据的持久化格式。

普通 IDS 的结构符和白式 IDS 语法请参考：

- [NightFurySL2001/bai-ids](https://github.com/NightFurySL2001/bai-ids)

## 基本规则

解析器会先处理 Unicode 转义，再解析 IDS 树和查询节点。查询预处理可能产生多个等效表达式，之后分别进入匹配层。

普通 IDS 结构仍然使用“⿰”“⿱”“⿲”“⿳”“⿸”“⿺”等结构符。下面的扩展语法不等同于普通字形数据中的一个字形部件。

## 通配部件 ⬚

⬚ 表示一个可替换的 IDS 单元：

```text
⿰贝⬚
```

这表示左部为“贝”、右部为任意可匹配部件的结构。它不是“任意 Unicode 字符”，候选仍受 IDS 结构、数据库数据和筛选条件限制。

## 组合搜索

### `<search=...>`

`<search=...>` 表示 AND 关系。逗号分隔的条件必须在同一个候选 IDS 表达式中分别找到：

```text
<search=长,马>
<search=幺,言,幺>
```

同一个候选 IDS 不能把不同 IDS 表达式中的命中部件拼接起来。搜索表达式可以嵌套 IDS 结构和 `<any=...>`。
重复条件需要在同一个 IDS 式中分别命中：`#(...)` 的同一笔画 token 不能被重复占用。单笔画条件可以命中 `#(...)` 中的笔画 token，包括负笔画；负号是 token 标记，不是笔画字形的一部分。

当一个条件本身包含逗号时，可以使用单引号或双引号：

```text
<search="<any=巾,忄>",亡>
<search='<any=巾,忄>',亡>
```

### `<any=...>`

`<any=...>` 表示 OR 关系，只需要其中一个条件匹配：

```text
⿰<any=巾,忄>亡
<search=<any=巾,忄>,亡>
```

`<any=...>` 内部不支持 `<residue=...>`。需要同时满足多个条件时，应使用 `<search=...>`。

### `<except=...>`

`<except=...>` 可以放在最外层，也可以放在 `<search=...>` 或 `<any=...>` 内。直接列出的条件表示排除满足其中任一项的结果：

```text
<except=虫,貴>
```

如果要排除同时满足“虫”和“貴”的结果，可以嵌套 `<search>`：

```text
<except=<search=虫,貴>>
```

同一层的 `<search>` 或 `<any>` 最多使用一个 `<except>` 子句，排除判断仍然在同一个候选 IDS 表达式内进行。

## 笔画条件

### `<stroke=...>`

`<stroke=...>` 表示当前 IDS 单元或字形的笔画数范围：

| 写法 | 含义 |
| --- | --- |
| `<stroke=12>` | 恰好 12 画 |
| `<stroke=-12>` | 不超过 12 画 |
| `<stroke=12->` | 不少于 12 画 |
| `<stroke=12-18>` | 12 至 18 画，含边界 |
| `<stroke=21~1>` | 以 21 画为中心，允许误差 1 画，即 20 至 22 画 |

~N 在预处理阶段转换为闭区间。笔画数根据 IDS 表达式计算并使用数据库缓存；无法可靠计算时，不能把该条件当作绝对精确的预过滤条件。

### `<residue=...>`

`<residue=...>` 只用于 `<search>` 上下文，单个搜索表达式至多出现一次。它表示除指定搜索部件以外的剩余部分的总笔画数，并且不考虑剩余部分的结构：

```text
<search=长,<residue=31->>
<search=水,<residue=12~2>>
```

`<residue=0>` 表示没有剩余部分。在适用的整字匹配场景中，它也可以命中该字本身及其等价 IDS 记录。

## 变量

`<var=...>` 用于在一次匹配中保持部件对应关系。变量名由 ASCII 字母、数字和下划线组成：

```text
⿱<var=a>隹
⿱<var=_a>⿰<var=_b>⬚
```

同名变量在同一次候选匹配中需要对应同一 IDS 单元。IWDS 导入产生的内部变量使用独立命名空间，通常形如 `<var=_a>`。

在 HV 匹配中，一个变量可以绑定连续的多个节点，不仅限于单个子节点。同名变量比较的是绑定部件，不只是文本写法。例如 `⿱<var=1>⿰<var=1><var=1>` 可以匹配 `䆐` 的三个“秦”，即使其中一个“秦”展开为 `[𡗗, 丿, 木d]`。小写 `d` 是“木”的后缀，不是独立节点。不同变量名不要求绑定不同部件。

全角字母和数字不会在普通 IDS 导入时自动转换成变量，因为它们也可能是实际字形部件。

## HV 展开范围标记

`▥` 和 `▤` 的方括号参数用于记录 HVExtract 产生的歧义来源，不是普通部件。格式为：

```text
▥[士=0:2](十一|口)
```

其中 `士=0:2` 表示候选结构中的半开区间 `[0, 2)` 对应原始字形“士”。多个来源可以用逗号分隔，例如 `[士=0:2,土=1:3]`。`glyph` 只记录 IDS.pdf 7.1 中明确要求唯一化区分的字形；没有这种歧义时不应人为添加范围标记。

该标记主要出现在 HV 缓存、详细匹配结果或等效查询中。解析器会保留它，匹配器据此避免把“土”和明确区分的“士”混为一谈。它与 `▥(...)` / `▤(...)` 的组合结构参数不同，也不应当把普通排列结构的 `|` 分隔点当作部件。
默认启用同 IDS 唯一化排除，HV 递归匹配时也会检查。CLI 的 `--disable-same-ids-exclusion` 或 Python 配置 `fuzzy_match.exclude_non_equivalent_same_ids = False` 可以关闭该限制。

## 原始 IDS 与派生缓存

数据库导入会保留原始 IDS，并生成供查询使用的派生缓存：

- 原始 IDS 是 `ids_lv0.txt` 等输入数据的可追溯定义；
- HVExtract 缓存保存一个原始 IDS 可能产生的多个结构展开；
- 笔画中性组合缓存只在组合检索时忽略小写笔画后缀的差异，例如把 `一t` 作为可组合部件，但不改变原始定义；
- 一级部件倒排索引将原始 IDS、HV 和笔画中性表达式的直接部件记录到 SQLite。它只用于适用的 `<search=...>` 查询的保守候选筛选，不取代完整匹配；缺失或旧版索引会在加载时重建或迁移；
- 私有库重新导入或缓存重建后，派生缓存需要重新生成。

因此，查询结果中的 `raw_ids` 与 `matched_ids` 可能不同；详细结果中的 `match_source` 和 `preprocess_rules` 用于区分命中的缓存来源。
## Unicode 转义

解析前可以使用 \uXXXX 和 \UXXXXXXXX：

```text
\u3402
\U0001F504赢贝女
```

转义会先转换为 Unicode 字符，再进入 IDS 解析和查询预处理。CLI、PowerShell、Shell 和 Python 自身也可能对反斜杠进行处理。

## U+1F504 🔄 替换查询

🔄（无法直接输入时可写成 \U0001F504）是查询预处理语法，用于表达“将一个字形中的指定部件替换为另一个部件”：

```text
\U0001F504赢贝女
```

上例表示在“赢”的 IDS 中查找“贝”，并将该部件替换为“女”。它只用于查询预处理，不要求上游 IDS 数据库存在对应的原始表达式。

## ▥、▤ 和 HV 展开

▥(...)、▤(...) 是扩展组合结构，也会被程序用于表示 HVExtract 和查询预处理产生的结构集合：

```text
▥(牛⬚)
▤(丶一𠃊巾)
```

它们不是忽略结构的通配符。匹配时仍会检查部件顺序、节点范围和对应关系。

## 重叠修饰符与定位

`⿻[M1|M2]AB` 保留一或两个有序重叠矩阵。矩阵可以是横向切片（`[:-2]`、`[1:]`）或逗号分隔的行（`[x,_x]`）；没有逗号的连续单元如 `[_x_]` 视为一行。空行也会保留，例如 `[,x]`。行内的字面符号为 `.、_、x、a、b、c、d、l、r`。

默认的 `ignore` 模式只匹配结构和部件，不限定修饰符。`constrained` 模式检查矩阵数量、顺序、类型、切片端点（包括端点是否省略）和字面行；查询没有修饰符时，只匹配同样没有修饰符的候选。当前不执行切片与穿插矩阵的语义归一化，例如 `[_x_]` 与 `[:-2]` 不会自动互认。

| 查询修饰符 | constrained 模式中的含义 |
| --- | --- |
| `[*:*]` | 一个切片矩阵，端点任意，包括省略端点 |
| `[?:x]` | 非法：`?` 不是切片端点通配符 |
| `[?]` | 恰好一行，可以是空行 |
| `[x,?]` | 字面行 `x` 后接恰好一行任意内容 |
| `[x,*]` | 字面行 `x` 后接一行或多行任意内容 |
| `[**]` | 恰好一个任意类型的矩阵 |
| `[**\|**]` | 恰好两个任意类型的矩阵 |
| `[***]` | 整个修饰符任意，包括没有修饰符 |

`?`、`*` 必须占据逗号分隔的一整行，不能替换 `_x` 内部的单个字符。`***` 必须占据整个修饰符，不能与 `|` 组合。这些通配符仅用于查询。

全包围、半包围定位支持非负数字和查询通配符 `[*]`，例如 `⿵[*]门⬚`，包括定位 0。它不会取消结构及部件限制，也不代表可以任意重排带定位数字的候选。

CLI 使用 `--overlap-match-mode constrained`；Python 使用 `options.overlap_match_mode = ids4c.OverlapMatchMode.CONSTRAINED`。这与 `--ignore-overlay` 不同：后者排除重叠命中，不是检查其修饰符。

## 包围结构重排与近似匹配

严格外部重排支持以下双向规则。A、B、C 代表部件，不是需要直接输入的变量名：

```text
⿸⿱ABC = ⿱A⿸BC    ⿸⿰ABC = ⿰A⿸BC
⿹⿱ABC = ⿱A⿹BC    ⿹⿰ABC = ⿰⿹ACB
⿺⿱ABC = ⿱⿺ACB    ⿺⿰ABC = ⿰A⿺BC
⿽⿱ABC = ⿱⿽ACB    ⿽⿰ABC = ⿰⿽ACB
⿵⿱ABC = ⿱A⿵BC
⿶⿱ABC = ⿱⿶ACB
⿷⿰ABC = ⿰A⿷BC
⿼⿰ABC = ⿰⿼ACB
```

嵌套包围也支持严格重排，例如 `⿵⿵ABC = ⿵A⿵BC`；适用时会考虑 HV 正则化后的 `▥`、`▤`。非零定位数字及 HV 来源范围会限制可用变换。

近似规则默认启用，独立于 IWDS 等级，包括 `⿵A⿱BC ≈ ⿵A⿵BC` 等嵌套包围布局，以及以下角部布局：

```text
⿰A⿱BC ≈ ⿸⿰ABC ≈ ⿺⿰ACB
⿰⿱ABC ≈ ⿹⿰ACB ≈ ⿽⿰BCA
⿱A⿰BC ≈ ⿸⿱ABC ≈ ⿹⿱ACB
⿱⿰ABC ≈ ⿺⿱ACB ≈ ⿽⿱BCA
```

这些是查找近似规则，不修改原始 IDS，也不是全局结构统合，可能增加结果。CLI 使用 `--strict-enclosure-match`、GUI 勾选 **Strict enclosure matching**，或 Python 设置 `options.strict_enclosure_match = True`，可关闭近似规则并保留严格重排。该开关不关闭 IWDS 或同 IDS 等价匹配。

## 其他扩展结构

当前解析器还识别：

- ㇯：减去指定部件，支持 `㇯[1]王一` 等数字消歧义形式，不支持 `㇯[*]...`；
- ⿻：重叠结构，修饰符与查询控制见前文；
- ⿾、⿿：扩展结构节点，按其参数参与匹配。

这些语法主要属于查询层。需要与其他程序交换数据时，建议保存原始 IDS，把特化表达式作为查询输入或预处理结果单独保存。

## 白式导入元数据

白式源文件中的 `(.,T)` 等逗号并列变体标识会把定义分配给独立的字形记录；`.` 表示无后缀字形。默认定义组与另类定义组通过 schema 8 的 `ids_entries.is_alternative` 保留。组标记是元数据，不是结构节点，也不是查询排除条件。导入时会校验笔画表达式，并拒绝查询专用通配符。旧白式数据库的重新导入要求见 [cli-zh.md](cli-zh.md#升级至-040)。
